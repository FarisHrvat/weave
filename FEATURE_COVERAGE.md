# Weave feature coverage

Checked against the named products' official feature pages on 14 October 2026; updated 16 October 2026 after further implementation, a full local test run and a layout pass. This is a working inventory of substantive capabilities, not a claim that every menu item in every product has been reproduced. "Built" means Weave exposes the workflow; it does not mean every provider and device has been tested. See `README.md` for verification limits. Weave now runs on macOS, Windows and Linux; where this table names a macOS tool (Keychain, Finder, Touch ID), [README.md](README.md#what-weave-needs-on-each-system) lists what Weave uses on the other systems.

## File transfer clients

Sources: [FileZilla Pro](https://filezillapro.com/), [WinSCP features](https://winscp.net/eng/docs/introduction), [WinSCP synchronization](https://winscp.net/eng/docs/task_synchronize), [Cyberduck protocols](https://docs.cyberduck.io/protocols/), [Cyberduck features](https://docs.cyberduck.io/cyberduck/).

| Capability seen in the named apps | Weave | Remaining work |
| --- | --- | --- |
| Local, SFTP, FTP, FTPS, WebDAV, S3 and Azure Blob dual-pane browsing and file operations | Built, including range and additive selection, batch queued copying, and confirmed batch deletion | S3 uses a path-style bucket URL, a signing region, an access key pair and an optional session token; real providers and more authentication methods need testing. |
| Transfer queue, pause/resume/retry, speed limits, history | Built, plus saved one-way and two-way folder sync jobs with 15-minute to 7-day intervals, manual runs, pause/resume, and recorded comparison and transfer errors | Jobs run while Weave is open or kept in the menu bar. An optional macOS LaunchAgent also wakes Weave every 15 minutes to run due jobs after it has fully quit; the scheduler lock prevents two processes owning the queue. LaunchAgent files and locking are tested, but actual login and quit-state behavior need native testing. |
| Directory comparison and one/two-way copy preview | Built, including one-way mirror preview and separately confirmed deletion of destination-only items after a fresh comparison. Local and SFTP copies attempt to preserve file times; FTP/FTPS uploads attempt MFMT, and WebDAV uploads send Nextcloud-compatible `X-OC-MTime`. Sync checks equal-sized newer files by checksum before copying. | Scheduled mirror jobs now delete destination extras unattended, only after all copies are done, never when the source folder looks empty, and at most 1000 items per run. FTP servers without MFMT and WebDAV servers without `X-OC-MTime` may report different timestamps after upload. Nextcloud compatibility needs a live-server check. |
| Remote text editing | Built-in UTF-8 editor supports files up to 1 MB. A separate external editing workflow checks out regular SFTP, FTP, FTPS, WebDAV or S3 files up to 512 MB to a private local copy, opens them in a macOS app, and uploads on request after checking both the local and remote file hashes. | Automatic upload on save is optional per editing copy: a watcher waits for the save to settle, uploads with the same hash checks, and turns itself off if the remote file changed. Limited to 512 MB; native testing with real editors remains. |
| WebDAV, S3 and cloud providers | WebDAV and S3-compatible browsing, editing and queued transfers pass disposable local-server tests. S3 accepts path-style, virtual-hosted and S3 Express directory bucket URLs, AWS CLI credentials and multipart uploads. Presets cover Amazon S3, Cloudflare R2, Backblaze B2, Wasabi and DigitalOcean Spaces. Native Dropbox, Google Drive and OneDrive profiles now have browser OAuth with PKCE and token refresh, plus listing, folder operations and file transfers through their APIs. | Cloud backends and sign-in were tested against disposable mock servers, not live accounts. Each cloud provider requires the user to register an app and enter its client ID (and Google client secret); Weave has no shared registered app. AWS and other live provider compatibility remains untested. |
| SCP, direct remote-to-remote routing, rsync and FXP | Same-profile SFTP copies use the server copy-data extension when available. SCP and rsync copies between this Mac and an SSH host join the transfer queue. A direct-SSH route between two hosts relays through this Mac without writing a local file; a disposable two-host test passes. FXP copies between two FTP or FTPS servers; FTPS requires consent for a clear server-to-server data channel. | SCP and rsync accept any path (rsync paths are quoted for the remote shell) and use key or agent authentication. FXP verifies the copy with XSHA256/XSHA1/XMD5/XCRC when both servers offer one, otherwise by size. Live NAS and provider checks remain. |
| Cryptomator vaults and temporary share URLs | **Cryptomator vault** in Files creates vault-format-8 vaults and unlocks formats 7 and 8, with either SIV_GCM or the older SIV_CTRMAC file encryption, on this Mac or in any synced folder: browse, add files and folders (encrypted before writing), decrypt to a folder, rename, delete, and change the vault password. Cross-checks pass in both directions with pycryptomator for format 8, and with an independent reference written from the specification for format 7. S3 files get signed download links (15 minutes to 7 days), and Nextcloud or ownCloud WebDAV files and folders get public links through their share API. | Format 6 and older, Cryptomator Hub vaults and vaults stored directly on SFTP, FTP or S3 servers are not supported. Share links were tested against mock servers, not live Nextcloud or AWS. |
| Batch scripting, automatic directory watching and scheduled sync | Saved scheduled sync is built; one-way jobs can also run when their source folder changes, whether the source is local (checked every 30 seconds) or on any connection (listed every 2 minutes to keep server load low). JSON copy plans validate local paths, preview and queue up to 200 transfers atomically. A bounded file script runner supports opening saved connections, navigation, listing, mkdir, delete, rename, get, put and sync, with a stop control and output log; local script behavior is tested. | Change checks compare names, types, sizes and modification times. File scripts have no recurring headless scheduler; remote scripts and running while Weave is fully quit need live testing. |
| Certificate pinning and broader authentication | FTPS and HTTPS WebDAV profiles can require up to three SHA-256 server certificate fingerprints in addition to macOS trust validation, so a new fingerprint can be added before rotation. A certificate inspector shows the server fingerprint and trust state. WebDAV and FTPS connections can present a client certificate from a PEM file with its key; disposable TLS-server tests check both. | Client certificates can now also be chosen from the Keychain: Weave exports only that identity (macOS asks permission for its key) into a private PEM file; a test does this with a real temporary keychain. Hardware-backed (non-exportable) identities cannot be used. Live certificate rotation remains untested. |

## Release gate

Feature parity and “better than all products” remain **unproven**, and the app is still an alpha. The work that cannot be finished from this Mac alone is:

- **Needs your accounts or app registrations:** live Azure Blob Storage, the Anthropic API (AI features), live Dropbox, Google Drive and OneDrive; browser sign-in for Bitbucket, Azure DevOps and Jira; live GitHub/GitLab Enterprise, Bitbucket, Azure DevOps, Jira, AWS and Nextcloud.
- **Needs a second Mac or a real synced folder:** team vault interoperability, simultaneous edits and conflict recovery.
- **Needs hardware or software not installed here:** USB serial adapters, Mosh, XQuartz, Windows App, fish, a VNC server, lrzsz (`sz`/`rz`), imgcat, wakeable hardware, and VPN/NAS setups.
- **Needs native checks on this Mac:** start at login and sync while quit, the global hotkey, Keychain export prompts, drag and drop, and VoiceOver.
- **Not supported:** Cryptomator format 6 and Hub vaults, vaults stored directly on SFTP/FTP/S3, and non-exportable (hardware) client certificates.

- **Not built:** Mercurial; Finder drives for SFTP, S3 and Azure (these need macFUSE, a third-party kernel extension); dragging tabs between windows; tmux control mode (`tmux -CC`); rlogin and XDMCP, which are left out deliberately because they send passwords unencrypted.
- **Notarization:** left out on purpose (it needs a paid Apple Developer membership); the DMG is ad hoc signed and macOS asks once before the first launch.
- **Security:** see [SECURITY.md](SECURITY.md); an independent security review is recommended before a public release.

Layout was checked at the minimum window size (980×650), 1440×900, 1920×1080 and 2560×1440, in light and dark themes, on the first-run screen and with data, by opening every page, Git tab and command-palette dialog with an automated overlap check.

Automated tests cover local and disposable servers only. The user plans to perform the physical device test after an honest ready notice.
